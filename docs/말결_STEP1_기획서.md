## 1. P.08 문제 정의서
 
### [슬라이드에 들어갈 최종 문구]
 
**① 우리 조가 발견한 불편 · 문제 상황**
> 신입 회계사는 선배·인차지에게 질문·부탁·보고를 보낼 때, 전할 내용은 알아도 **무엇을 어떤 순서로 말할지** 정리하지 못한다.
> 해본 것·막힌 지점·내 판단이 빠지면 "그래서 뭘 해봤어?"라는 되물음이 오고, 너무 돌려 말하면 기한과 요청이 흐려진다.
> GPT에 맡겨도 상대·상황·말투를 매번 설명해야 하고, 다듬어진 문장에서 원래 의도가 빠지지 않았는지 다시 확인해야 한다.
> *(근거: 조원 실제 사례 2~3건 · 미니 설문 결과 삽입 [팀 기입])*
 
**② 이 앱을 쓸 사람은? (타깃 사용자 · 고객 분석)**
> 입사 1년 이내 감사본부 신입 회계사(스태프).
> · 하루: 현장·조서 작업 중 선배·인차지에게 메신저로 질문, 자료 요청, 진행 보고를 자주 보낸다.
> · 번거로운 순간: "이걸 어떻게 물어보지?" 하며 메시지를 썼다 지웠다 할 때.
> · 원하는 것: 한 번에 이해되는 메시지로 바쁜 선배의 시간을 덜 뺏는 것.
 
**③ 선택한 트랙**
> ☑ TRACK 1 개인 — 나 또는 비슷한 상황의 사람
 
**④ 해결 시 기대 효과** *(기대효과 · 테스트로 검증 예정)*
> 상황 카드를 고르고 빈칸만 채우면 빠진 정보 없는 메시지가 완성된다.
> → 작성·수정 시간과 선배의 되물음 감소, 수정 이유를 반복해 보며 좋은 질문 구조를 익힘.
 
**⑤ 한 줄 문제 정의**
> "**입사 1년 이내 신입 회계사**가 **선배·인차지에게 질문·부탁·보고할 때 무엇을 어떤 순서로 말할지 몰라** 겪는 **핵심 정보 누락과 반복 수정**을, **상황별 구조화와 의도 체크로 메시지를 완성하는 '말결'**로 해결한다."
 
### [그렇게 작성한 이유]
- 평가 1항목(25점)의 "문제와 핵심 기능이 직접 연결되는가"에 맞추기 위해, 한 줄 정의의 문제(정보 누락)와 해결(구조화·의도 체크)이 기능 ①②와 1:1로 대응하도록 썼습니다.
- 타깃을 "직장인"이 아니라 **감사본부 신입 + 선배·인차지 + 메신저**로 좁혔습니다. 조원 9명이 곧 타깃이므로 직접 검증이 가능하고, 심사위원(회계법인)이 장면을 바로 떠올릴 수 있습니다.
- "자주 보낸다"처럼 빈도는 확정하지 않았습니다. 미니 설문 결과가 나오면 숫자로 바꿉니다(아래 7-1).
- ④는 "기대효과"로 명시했습니다. "능력 향상"이 아니라 "구조를 익힘" 수준으로 표현했습니다.

## 2. P.09 IMPACT · Before → After
 
### [슬라이드에 들어갈 최종 문구]
 
| | BEFORE · 앱이 없던 하루 | AFTER · 말결을 쓴 하루 |
|---|---|---|
| **상황** | 재고평가충당금 계산이 맞지 않는다. 선배에게 물어야 하는데 바빠 보인다. | 같은 순간, 말결의 '질문 준비실'을 연다. |
| **행동** | 메시지를 썼다 지웠다 → GPT에 상황을 설명하고 2~3번 수정 → 보냈더니 "전기 산식은 확인했어?"라는 되물음 | 한 줄 입력 → AI가 상황·해본 것·막힌 지점·선택지·내 판단으로 정리 → 빈칸만 보충 → 의도 체크 확인 후 복사 |
| **감정** | 막막함 · 눈치 · "또 물어봐도 되나" 하는 부담 | 정리됐다는 안도감 · 한 번에 묻는 자신감 |
 
**① 숫자로 보여주는 변화** *(1차 테스트 후 기입)*
- 소요 시간: **__분 → __분** [측정 예정]
- 필요한 단계: **5단계 → 3단계** *(설계 기준 흐름)*
- 함께 쓰는 사람: **__명** [1차 테스트 참여 인원, 목표 5명 이상]
**② 무대에서 외칠 한 문장**
> "이제 **'이걸 어떻게 물어보지?'**는, **빈칸 몇 개로 가벼워**집니다."
 
### [그렇게 작성한 이유]
- 기능을 나열하는 대신, 대표 시연 사례(재고평가충당금) 하나로 Before와 After를 같은 장면에 놓아 대비를 만들었습니다. 시연(P.17)과 같은 사례라 일관됩니다.
- Before의 "2~3번 수정"과 "되물음"은 현재 **가정**입니다. 미니 설문으로 뒷받침되지 않으면 문구를 조정합니다.
- 시간 칸은 측정 전이라 비워 두었습니다. 단계 수는 측정값이 아니라 흐름을 비교한 값이므로 "설계 기준"으로 표시했습니다.
  - Before: 작성 → GPT에 상황 설명 → 반복 수정 → 전송 → 되물음에 답변
  - After: 카드 선택·한 줄 입력 → 빈칸 보충 → 확인·복사

## 3. P.10 기획 · UX 설계
 
### [슬라이드에 들어갈 최종 문구]
 
**① 앱 이름 & 한 줄 소개**
> **말결** — 한 줄 고민을 빠짐없는 메시지로. 구조를 먼저 잡고, 의도는 지킨 채 나다운 말로 다듬는 신입 커뮤니케이션 도우미
> *마음은 그대로, 표현은 나답게.*
 
**② 핵심 기능 (3가지 이내)**
> 1) **상황별 구조화 작성 (핵심)** — 상황 카드를 고르고 한 줄로 쓰면, AI가 필요한 칸으로 정리하고 빈칸은 되묻는다
> 2) **의도 체크 + 수정 이유** — 내가 확인한 항목(기한·요청·판단)이 문장에 모두 남았는지 ✓로 보여주고, 왜 이렇게 다듬었는지 알려준다
> 3) **내 말투 프로필** — 문장 길이·요청 방식·끝맺음과 마음에 든 문장을 저장해 다음 제안에 반영한다
 
**③ 사용자 여정**
> 홈(카드 선택 · 한 줄 입력) → 구조화 확인(빈칸 보충 · 받는 사람 선택) → 결과(내 말투안 + 대안 2 · 의도 체크 · 복사) → 내 말투(첫 방문 2~3문항 · 언제든 수정)
 
**④ 화면 스케치 · 와이어프레임**
> 4개 화면 와이어프레임 캡처 삽입 (아래 5장 화면 구성안 기준)
 
### [그렇게 작성한 이유]
- 핵심 1개와 보조 2개 구조(가이드 TIP)를 따랐습니다. 기존 3번 기능이던 "커뮤니케이션 피드백"은 실체가 모호해 2번의 "수정 이유"로 흡수했습니다.
- 기능 2에는 "내가 확인한 항목"이라는 표현을 넣었습니다. AI가 혼자 판정하는 것이 아니라 **사용자가 확정한 의도를 기준**으로 확인한다는 점이 일반 GPT와 다른 지점이기 때문입니다.
- 기능 3은 "학습한다"가 아니라 **"저장해 반영한다"**로 썼습니다. 실제 구현 방식(설정과 선호 문장을 context에 포함)과 일치하는 표현입니다.

## 5. 빌드팀 인계용 화면 구성안
 
### 5-0. 공통 원칙
- **로그인 없음**, 데이터는 **브라우저 저장(localStorage)**에만 둠 (말투 프로필 · 선호 문장)
- 결과물은 **메신저용 짧은 글**만 (이메일 형식 제외)
- 받는 사람은 **선배 / 인차지 / 동기** 3개 (클라이언트 제외)
- **보안 안내 고정 문구**: "클라이언트명·금액 등 기밀 정보는 'A사', 'X원'처럼 바꿔 입력하세요." (홈과 입력창 하단)
- AI는 **빈 정보를 지어내지 않는다**. 추론하지 못한 칸은 비워 두고 사용자에게 묻는다.
### 5-1. 화면 1 · 홈
| 요소 | 내용 |
|---|---|
| 제목 | "어떤 말을 전하고 싶나요?" |
| 상황 카드 3개 | 질문 준비실 / 부탁 한 장 / 한 줄 상황보고 (카드마다 "이럴 때" 한 줄 설명) |
| 자연어 입력창 | 카드를 선택한 뒤 활성화. placeholder 예: "재고평가충당금 계산이 안 맞는데 선배한테 물어보고 싶어요" |
| 버튼 | [정리하기] → 화면 2 |
| 보조 | 우상단 "내 말투" 진입, 보안 안내 문구 |
| 첫 방문 | 프로필이 없으면 상단 배너 "30초 만에 내 말투 설정하기(건너뛰기 가능)" |
 
### 5-2. 화면 2 · 구조화 확인
- AI가 한 줄 입력을 카드별 칸에 나눠 채움 → 사용자가 수정하고 빈칸을 보충
- 비어 있는 필수 칸은 **노란색 + AI 질문**으로 표시 (예: "어떤 걸 먼저 확인해 보셨나요?")
- 상단에 받는 사람 선택: 선배 / 인차지 / 동기 (필수)
- 버튼: [메시지 만들기] (필수 칸이 모두 채워져야 활성화) → 화면 3
**카드별 입력 칸** (* = 필수)
 
| 질문 준비실 | 부탁 한 장 (일정 조정 포함) | 한 줄 상황보고 |
|---|---|---|
| 상황* | 요청 내용* | 완료한 것* |
| 해본 것* | 기한* | 진행 중인 것 |
| 막힌 지점* | 필요한 결과(형태) | 막힌 점 |
| 선택지 | 이유·배경 | 도움 요청 |
| 내 판단 | 대안·조건 | 다음 예정·완료 예상 시점 |
| 묻고 싶은 것* | 상대 동의 필요 여부 (체크) | |
 
### 5-3. 화면 3 · 결과
| 요소 | 내용 |
|---|---|
| 탭 3개 | **내 말투안(기본)** / 더 간결하게 / 더 부드럽게 |
| 메시지 본문 | 편집 가능한 텍스트 영역 |
| 의도 체크 | 화면 2에서 채운 칸 하나당 1줄. ✓ 포함됨 / ⚠ 누락 가능 |
| 수정 이유 | 2~3줄. 예: "막힌 지점을 앞에 둬서 선배가 바로 답할 수 있어요" |
| 버튼 | [복사] [다시 만들기] [이 표현을 내 말투에 반영] [구조 수정](← 화면 2로) |
 
**의도 체크 판정 규칙** (AI가 스스로 채점하지 않게 하는 장치)
1. 체크 항목 = 화면 2에서 **사용자가 확정한 칸**의 값 (AI가 새로 뽑지 않음)
2. AI는 각 항목에 대해 메시지 안의 **근거 구절(원문 그대로)**을 함께 반환
3. 앱(코드)이 그 구절이 실제 메시지에 들어 있는지 문자열로 확인 → 있으면 ✓, 없거나 비어 있으면 ⚠
4. 사용자가 본문을 편집하면 3을 다시 실행
### 5-4. 화면 4 · 내 말투
- **첫 방문 온보딩(건너뛰기 가능)**: 같은 뜻의 문장 A/B 중 "어느 쪽이 나답나요?" 3문항. 선택 결과를 설정값에 **규칙으로 바로 매핑**합니다(AI 불필요).
  - 1문항 → 문장 길이 / 2문항 → 요청 방식 / 3문항 → 끝맺음
- **설정**: 문장 길이(짧게/보통/충분히 설명) · 요청 방식(직접적으로/부드럽게/매우 조심스럽게) · 끝맺음(합니다체/해요체) · 피하고 싶은 표현(선택, 자유 입력)
- **선호 문장**: 결과 화면에서 반영한 문장 목록 (최근 5개 유지, 삭제 가능)
- 건너뛴 경우 기본값: 보통 / 부드럽게 / 합니다체
### 5-5. AI 호출 2회 · 출력 형식 (JSON으로 고정)
**호출 1 · 구조화** (화면 1 → 2)
- 입력: 카드 종류, 한 줄 입력
- 출력: `{ fields: {칸이름: 값 또는 null}, followups: {비어 있는 칸: "되묻는 질문"} }`
- 규칙: 입력에 없는 내용은 null로 두고 지어내지 않음
**호출 2 · 메시지 생성** (화면 2 → 3)
- 입력: 카드 종류, 확정된 칸, 받는 사람, 말투 프로필, 선호 문장(최대 5개)
- 출력: `{ variants: [{type: "mine"|"concise"|"soft", text, evidence: {칸이름: "근거 구절"}}], reasons: ["…","…"] }`
- 규칙: 확정된 칸의 내용을 빠뜨리거나 바꾸지 않음 / 메신저 길이(3~5문장) / 받는 사람에 맞는 호칭과 존댓말
### 5-6. MVP vs 추후
| MVP (이번 기간) | 추후 확장 |
|---|---|
| 카드 3개 · 화면 4개 · AI 호출 2회 | 거절도 괜찮아 (시간이 남으면 1순위로 추가) |
