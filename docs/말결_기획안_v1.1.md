## 01 한눈에 보기

**한 줄 문제 정의**

“직장에서 질문·부탁·보고·피드백·거절을 해야 하는 신입 구성원이 무엇을 어떤 순서로, 어떤 표현으로 말할지 몰라 겪는 정보 누락과 오해를, 구조화 → 의도 보존 표현 → 수정 이유로 돕는 ‘말결’로 해결한다.”

| 항목 | 내용 |
|---|---|
| 앱 이름 | 말결 — 말할 내용은 구조화하고, 의도는 지킨 채 표현을 다듬는 신입 커뮤니케이션 도우미 |
| 트랙 | TRACK 1 · 개인 (제안자 초안 기준) |
| 타깃 사용자 | 상사·선배·동료·클라이언트와 질문·부탁·보고·피드백·거절을 할 때 표현을 고민하는 신입 구성원 · 첫 검증: 우리 조 신규입사자 동기 |
| 핵심 기능 (3) | ① 상황별 커뮤니케이션 구조화 ② 의도 보존형 표현 제안 ③ 최소한의 말투 개인화 + 커뮤니케이션 피드백 |
| 상황 카드 (6) | 질문 준비실 · 부탁 한 장 · 피드백 연습장 · 의도 확인 카드 · 한 줄 상황보고 · 거절도 괜찮아 — 6개 기능이 아니라 공통 엔진 위의 상황별 입력 템플릿 |
| 화면 (4) | 홈 → 상황·의도 구체화 → 표현 비교 + 의도 보존 확인 → 내 말투 |
| 1순위 차별점 | 문장부터 쓰지 않고 무엇을 말할지부터 구조화하고, 다듬은 뒤 원래 의도(기한·요청·판단·조건)가 남았는지 확인한다 |
| 대표 시연 사례 | 질문 준비실 · “재고평가충당금 계산이 잘 안 맞는데 선배한테 물어보고 싶어요.” |
| 일정 | 기획 확정 10/02(가이드 마감) · 구현 목표 10/08 · 내부 리뷰 [팀 기입] · 크로스 피드백 [팀 기입] · 제출 [팀 기입] |

## 02 문제 정의

신입 구성원은 전할 내용 자체는 알고 있어도 “무엇을 어떤 순서로” 말해야 하는지, “어떤 표현을 써야 오해 없이” 전달되는지를 어려워한다.

**반복되는 문제 4가지**

| # | 문제 | 구체적인 모습 |
|---|---|---|
| 1 | 질문할 때 필요한 정보를 빠뜨린다 | 어떤 상황이 발생했는지, 무엇을 해보았는지, 어디서 막혔는지, 어떤 선택지가 있는지, 내 판단은 무엇인지, 무엇을 묻고 싶은지를 구조적으로 전달하지 못한다. 좋은 질문의 구조(가설): 상황 → 시도한 것 → 막힌 지점 → 선택지 → 내 판단 → 질문 |
| 2 | 관계·상황에 맞는 표현을 찾기 어렵다 | 같은 내용도 상사/선배/동료/클라이언트마다 적절한 표현이 다르다. 너무 직접적이면 무례하게, 너무 완곡하면 의도가 흐려진다. |
| 3 | 서로 다르게 이해해 문제가 생긴다 | 상사–부하, 클라이언트–회계사, 동기 사이 모두에서 다른 의미로 받아들여 재확인·재작업·오해가 생길 수 있다. |
| 4 | 일반 GPT를 써도 입력 부담이 크다 | 누구에게, 어떤 상황에서, 무엇을, 어떤 말투로 전할지 매번 다시 설명해야 하고, 다듬어진 문장에서 원래 의도가 빠지지 않았는지 다시 확인해야 한다. |

**현재 대안과 한계**

| 현재 대안 | 하는 방식 | 한계 |
|---|---|---|
| 혼자 작성 | 메신저 창에서 썼다 지웠다 반복 | 무엇이 빠졌는지 스스로 알기 어렵고 시간이 든다 |
| 동기·지인에게 물어보기 | “이렇게 보내도 될까?” 확인 | 상대도 신입이라 기준이 비슷하고, 매번 부탁하기 부담스럽다 |
| 일반 생성형 AI | 상황을 설명하고 문장을 고쳐 달라고 요청 | 매번 맥락 재설명, 정보가 부족해도 그럴듯하게 채움, 지나치게 딱딱하거나 나답지 않아 다시 고침, 의도 누락 여부를 직접 확인해야 함 |

**근거 (팀 기입 필요)** — 위 문제는 팀 기획 정보와 제안자 초안에 기반한 가설이다. P.08의 설득력을 위해 조원 실제 사례 2~3건과 미니 설문(11장) 결과를 추가한다. [팀 기입]

## 03 타깃 사용자

| 구분 | 내용 |
|---|---|
| 누구 | 상사·선배·동료·클라이언트와 질문·부탁·보고·피드백·거절을 해야 하는 신입 구성원. 첫 검증 대상: 우리 조 신규입사자 동기 |
| 언제 | 업무 중 메신저로 무언가를 묻거나 요청·보고해야 하는데 “이걸 어떻게 말하지?” 하며 메시지를 썼다 지웠다 할 때 |
| 왜 불편한가 | 내용은 아는데 순서·빠진 정보·표현 수위를 판단할 기준이 없다. 바쁜 상대에게 두 번 묻게 될까 봐 부담된다. |
| 원하는 것 | 한 번에, 오해 없이, 나답게 전달하는 것. 그리고 다음엔 스스로 더 잘 쓰는 것. |

**대표 사용 장면 · 질문 준비실**

신입 입력 — “재고평가충당금 계산이 잘 안 맞는데 선배한테 물어보고 싶어요.”
말결은 바로 문장을 만들지 않고 먼저 구조화한다.

| 칸 | 내용 |
|---|---|
| 상황 | 재고평가충당금 계산 중 금액 불일치 |
| 해본 것 | 전기 산식 확인 · 당기 재고 데이터 재검토 |
| 막힌 지점 | 두 가지 계산 방식 중 어떤 방식을 써야 하는지 확신 없음 |
| 선택지 | A 방식 / B 방식 |
| 내 판단 | A 방식이 전기 처리와 일관되어 보임 |
| 질문 | A 방식으로 처리하는 것이 맞는지 확인 요청 |

그다음 상대(선배)와 상황에 맞는 메시지로 변환한다. → 이 과정이 “좋은 업무 커뮤니케이션 프로세스를 UX로 만든 앱”임을 보여주는 핵심 장면이다.

## 04 제품 철학과 가치

말결은 단순한 문장 수정기가 아니다. “AI가 대신 말해주는 앱이 아니라, 더 잘 말할 수 있게 도와주는 앱.”

| | 내용 |
|---|---|
| A · 구조화 | 무엇을 말해야 하는가를 정리한다. 상황별로 필요한 항목을 묻고, 빠진 정보는 되묻는다. |
| B · 표현 | 사용자의 핵심 의도를 유지한 채 상대와 상황에 맞는 표현을 제안한다. |
| C · 학습 | 왜 이렇게 표현했는지 보여주고, 반복 사용으로 좋은 구조를 참고하고 익히도록 돕는다. (기대효과) |

**표현 원칙**
- “커뮤니케이션 능력이 향상된다”는 검증 전이므로 기대효과로만 표현한다.
- “AI가 사용자의 말투를 학습한다”라고 쓰지 않는다. 실제로는 설정 · 선호 · 선택 문장을 저장해 다음 요청의 context에 포함하는 구조다.
- 모든 상황을 해결하려 하지 않는다. 하나의 핵심 흐름이 끝까지 작동하는 것을 우선한다.

**말투 예시 · 같은 사실, 다른 사람**

사실: 오늘 완료하기 어렵고, 내일 오전 10시까지 전달해도 되는지 묻고 싶다.

| 사용자 | 표현 |
|---|---|
| 간결한 표현을 선호하는 사용자 | “오늘까지 완료하기는 어렵습니다. 내일 오전 10시까지 전달해도 괜찮을까요?” |
| 조심스럽게 요청하는 사용자 | “일정을 조정할 수 있을지 여쭙습니다. 오늘까지 완료하기는 어려운데, 내일 오전 10시까지 전달해도 괜찮을까요?” |

## 05 핵심 기능

| 문제 (02장) | 대응 기능 |
|---|---|
| 1. 정보 누락 | ① 상황별 커뮤니케이션 구조화 |
| 2. 표현 수위 · 3. 오해 | ② 의도 보존형 표현 제안 (의도 체크) |
| 4. GPT 재설명 부담 | ① 카드 템플릿 + ③ 말투 프로필 저장 |

### ① 상황별 커뮤니케이션 구조화 (핵심)

상황 카드를 고르거나 자유 입력하면, 카드별 입력 질문으로 말할 내용을 먼저 정리한다. AI가 자유 입력을 칸에 나눠 채우고, 비어 있는 칸은 되묻는다.

| 상황 카드 | 사용자가 필요한 순간 | 정리하는 구조 (입력 질문) |
|---|---|---|
| 질문 준비실 | “무엇부터 설명하고 질문해야 할까?” | 상황 · 시도한 것 · 막힌 지점 · 선택지 · 내 판단 · 궁금한 점 |
| 부탁 한 장 | “무엇을 어떻게 부탁해야 할까?” | 요청 내용 · 기한 · 필요한 결과 |
| 피드백 연습장 | “개선 의견을 어떻게 전할까?” | 관찰한 사실 · 영향 · 바라는 행동 |
| 의도 확인 카드 | “상대의 말이 애매한데 어떻게 되물을까?” | 받은 메시지 · 확인할 부분 → 되묻는 문장 (입력 성격 다름) |
| 한 줄 상황보고 | “진행 상황을 어디까지 설명해야 할까?” | 완료 · 진행 · 막힌 점 · 도움 요청 |
| 거절도 괜찮아 | “관계를 지키면서 내 한계를 어떻게 말할까?” | 거절 / 부분 수락 / 대안 제시 중 의도 · 이유 · 대안 |

공통: 받는 사람(상사 · 선배 · 동료 · 클라이언트), 반드시 전달할 내용, 기한/조건/대안. 6개 카드는 하나의 엔진에서 입력 질문과 프롬프트만 바뀐다.

### ② 의도 보존형 표현 제안 (보조 1 · 핵심 차별점)

정리된 구조를 간결하게 / 부드럽게 / 명확하게 세 가지 표현으로 비교해 보여주고, 다듬는 과정에서 핵심 사실이 사라지지 않았는지 의도 체크로 시각적으로 확인시킨다.

- 의도 체크 예시: ✓ 오늘 완료 어려움 · ✓ 내일 오전 10시 · ✓ 일정 변경 요청 · ✓ 상대방 동의 필요
- 확인 대상: 일정 · 기한 · 요청 · 판단 · 조건 · 대안 · 상대방 동의 필요 여부
- 판정 방식 제안 (빌드팀 확인 필요): AI가 의도를 뽑고 AI가 지켜졌는지 판정하면 “자기 채점”이 된다. 그래서 ① 체크 항목 = 화면 2에서 사용자가 확인한 칸 → ② AI는 항목마다 메시지 속 근거 구절을 함께 반환 → ③ 앱(코드)이 그 구절이 실제 문장에 있는지 확인해 ✓ / ⚠(누락 가능)을 표시한다. 사용자가 문장을 고치면 ③을 다시 실행한다.

### ③ 최소한의 말투 개인화 + 커뮤니케이션 피드백 (보조 2)

| 구성 | 내용 |
|---|---|
| 말투 프로필 | 문장 길이(짧게/보통/충분히 설명) · 격식 · 요청 방식(직접적으로/부드럽게/매우 조심스럽게) · 끝맺음(합니다체/해요체) · 피하고 싶은 표현 · 선호한 예문 |
| 초기 온보딩 | 같은 의미의 문장 2~3개 중 “어느 쪽이 나답나요?” 선택 → 프로필 초안 → 사용자가 수정 |
| 내 말투에 반영 | 결과 화면에서 고른 문장을 선호 예문으로 저장 → 다음 요청 context에 포함 |
| 커뮤니케이션 피드백 | 정의 제안: 결과마다 “왜 이렇게 바꿨는지” 2~3줄로 설명(수정 이유). 원문에서 범위가 정의되지 않아 팀 확정 필요 |

MVP 저장 범위: 문장 길이 · 요청 방식 · 말투 · 끝맺음 · 선호한 예문. 상황별 말투 차이와 장기 memory는 MVP 밖.

## 06 사용자 흐름 · 화면 구성

① 홈 (자유 입력 또는 상황 카드 선택) › ② 상황·의도 구체화 (상대 · 상황 · 반드시 전달할 내용 · 기한/조건/대안) › ③ 표현 비교 + 의도 확인 (3가지 표현 · 의도 체크 · 수정 이유 · 복사) › ④ 내 말투 (문장 길이 · 요청 방식 · 끝맺음 · 선호 예시)

와이어프레임 초안 · 예시 문구는 대표 사용 사례 기준 (PPT P.10과 동일) → `docs/design/wireframe.png`

| 화면 | 구성 요소 | 동작 |
|---|---|---|
| ① 홈 | “어떤 말을 전하고 싶나요?” · 자연어 입력창 · 상황 카드 6개 · 내 말투 진입 · 기밀정보 입력 주의 안내 | [정리하기] 또는 카드 선택 → ② |
| ② 상황·의도 구체화 | 선택한 카드의 입력 질문 · 받는 사람(상사/선배/동료/클라이언트) · AI가 채운 칸 · 빈칸은 강조 + 되묻는 질문 | 필수 칸 완료 시 [표현 만들기] → ③ |
| ③ 표현 비교 + 의도 확인 | 간결하게/부드럽게/명확하게 탭 · 편집 가능한 본문 · 의도 체크 목록 · 수정 이유 | [복사] [다시 만들기] [이 표현을 내 말투에 반영] [구조 수정 → ②] |
| ④ 내 말투 | 첫 방문 A/B 선택 · 설정 항목 · 선호 예문 목록(삭제 가능) | [저장] → 다음 요청에 반영 |

**시연 시나리오 (1~2분)**
1. 홈 → 질문 준비실 → “재고평가충당금 계산이 잘 안 맞는데 선배한테 물어보고 싶어요.”
2. ②에서 AI가 상황·막힌 지점을 채우고 빈칸(내 판단)을 되물음 → 보충
3. ③에서 세 가지 표현 비교 → 의도 체크 ✓ 확인 → 수정 이유 읽기 → [복사]
4. ④에서 요청 방식을 “조심스럽게”로 바꾼 뒤 다시 만들기 → 같은 의도, 다른 말투 확인

## 07 일반 GPT 대비 차별점

| 관점 | 일반 GPT 채팅 | 말결 |
|---|---|---|
| 시작 | 빈 입력창 · 상황을 매번 설명 | 상황 카드 · 필요한 입력 구조 제공 |
| 정보가 부족할 때 | 그럴듯하게 채워 바로 문장 생성 | 무엇을 말할지부터 구조화 · 빈칸은 되묻기 |
| 다듬은 뒤 | 원래 의도 유지 여부를 사용자가 직접 확인 | 의도 체크로 기한·요청·판단·조건 보존 확인 |
| 말투 | 매번 지시하거나 별도 설정 | 말투 설정 · 선호 표현을 다음 제안에 반영 |
| 학습 | 결과 문장만 제공 | 수정 이유 제공 · 좋은 구조를 반복해서 참고 |

**반론 검토 · “그냥 ChatGPT에 고쳐 달라고 하면 되지 않나?”**
- 약한 답: “말투를 기억한다.” → ChatGPT의 메모리·맞춤 지침·GPTs로도 가능하므로 이것만으로는 반박당한다.
- 버티는 답: ① 문장 생성 전에 구조를 먼저 묻는 흐름 자체가 좋은 질문을 만든다(GPT는 바로 써 준다). ② 사용자가 확인한 의도를 기준으로 결과를 검증한다. ③ 상황 카드로 프롬프트 작성 부담 없이 시작한다.
- → 발표 1순위 메시지는 “구조 먼저 + 의도 보존 확인”, 말투 개인화는 보조로 둔다.

**확장 가능성**
- 상황 확장: 같은 엔진에 카드(입력 질문 + 프롬프트)만 추가 — 예: 회의 요약 공유, 사과
- 사용자 확장: 다른 직무 신입, 클라이언트 커뮤니케이션 전용 카드
- 조직 확장 (추후): 팀이 검증한 좋은 질문 구조를 템플릿으로 공유
- 사내 도구 연동 (추후): Accounting Insight · ChatPwC 등과 연동해, 말결에서 구조화한 질문을 사내 지식·AI 도구에 바로 넘겨 더 정확한 답을 받는 흐름으로 확장 가능성 · 보안·정책 확인 필요

## 08 Before → After

| | BEFORE · 앱이 없던 하루 | AFTER · 말결을 쓴 하루 (기대) |
|---|---|---|
| 상황 | 재고평가충당금 계산이 맞지 않는다. 바빠 보이는 선배에게 물어야 한다. | 같은 순간, 말결에서 ‘질문 준비실’을 연다. |
| 행동 | 썼다 지웠다 → GPT에 상황 설명 후 여러 번 수정 → 보낸 뒤 “뭘 해봤어?” 되물음 | 한 줄 입력 → 상황·해본 것·막힌 지점·내 판단으로 정리 → 표현 비교 · 의도 체크 후 복사 |
| 감정 | 막막함 · 눈치 · ‘또 물어봐도 되나’ 하는 부담 | 정리됐다는 안도감 · 한 번에 묻는 자신감 |

- Before 흐름: “이걸 어떻게 물어보지?” → 장황한 설명 → 핵심 질문 누락 → 여러 번 수정 → GPT에 재설명 → 상대의 되물음 → 왕복 증가
- After 흐름: 상황 선택 → 필요한 정보 구조화 → 상대/의도/조건 입력 → 표현 대안 비교 → 의도 보존 확인 → 복사/전송

**기대 변화** (모두 검증 전 · 목표치는 테스트 후 실측값으로 교체)

| 기대 변화 | 목표치 (가설) | 확인 방법 (11장) |
|---|---|---|
| 작성 시간 감소 | 5분 → 2분 | 과제별 메시지 완성 시간 |
| 메시지 수정 횟수 감소 | 3번 → 1번 | 보내기 전 수정 횟수 |
| 추가 확인 대화 감소 | 되물음 2건 → 0건 | 받는 사람 역할 평가: 추가 질문 필요 여부 |
| 의도 전달 명확성 증가 | 빠진 핵심 정보 3개 → 0개 (6개 중) | 원래 의도 보존 여부 · 누락 개수 · 이해 쉬움(5점) |
| 질문의 구체화 → 더 좋은 아웃풋 | — | 상황·의도 구체화(화면 ②)로 막연한 질문 대신 구체적 질문 작성. 받는 사람의 “답하기 쉬움”(5점) · 표현 만족도로 확인 |
| 반복 사용을 통한 구조 학습 | — | “다음엔 스스로 더 잘 쓸 수 있을 것 같다”(5점) |
| 실제 사용 의향 | 9명 중 7명 | “실제 업무에서 다시 쓰겠다” 응답 수 |

**기대효과 추가 · 질문의 질이 올라간다** — 신입은 질문을 막연하고 짧게(“이거 어떻게 해요?”) 하는 경향이 있다. 화면 ②의 상황·의도 구체화를 거치면 상황·해본 것·막힌 지점·내 판단이 담긴 구체적인 질문이 만들어져, 상대에게서 더 정확하고 좋은 답(아웃풋)을 얻을 수 있다. 같은 이유로 AI가 만드는 표현의 품질도 높아진다. (기대효과)

**무대에서 외칠 한 문장** — “이제 ‘이걸 어떻게 말하지?’는, 빈칸 몇 개로 가벼워집니다.”

## 09 MVP 범위

**MVP 원칙**: 3~5개 화면 (현재 4개) · 1~2분 이내 시연 가능 · 하나의 핵심 사용 흐름이 끝까지 작동 · 다양한 기능보다 완성도 우선

| MVP (10/08 구현 목표) | MVP 밖 (원문 Out of Scope + 추후) |
|---|---|
| 화면 4개 · 공통 엔진 1개 | 실제 fine-tuning |
| 상황 카드 6개 (입력 질문 + 프롬프트) | 복잡한 장기 사용자 memory |
| 시연·테스트 우선순위: 질문 준비실 > 부탁 한 장 > 한 줄 상황보고 > 거절도 괜찮아 | 사내 메신저 직접 전송 |
| 간결/부드럽게/명확하게 비교 + 의도 체크 + 수정 이유 | 모든 커뮤니케이션 상황 지원 |
| 말투 프로필(5개 항목) + 선호 예문 저장 | 실제 회사 내부 데이터 연동 |
| 복사 · 다시 만들기 | 과도한 자동화 |
| 기밀정보 입력 주의 안내 | (추후 후보) 상황별 말투 차이, 작성 히스토리, 로그인 |

**범위 주의 · 빌드팀과 확인할 것** — 6개 카드를 모두 화면에 보여주면 심사위원은 모두 작동하길 기대한다. 시간이 부족할 경우 시연에 쓰지 않는 카드를 “준비 중”으로 표시할지, 카드 수를 줄일지를 10/08 이전에 정한다. 특히 의도 확인 카드는 ‘받은 메시지 해석’이라 다른 카드와 입력 흐름이 다르다.

## 10 구현 구조 · 빌드팀 확인 필요

| 항목 | 제안 |
|---|---|
| AI 호출 1 · 구조화 | 입력: 카드 종류 + 자유 입력 → 출력: 카드별 칸 값(모르면 null) + 빈칸별 되묻는 질문. 입력에 없는 내용은 지어내지 않음. |
| AI 호출 2 · 표현 생성 | 입력: 확정된 칸 + 받는 사람 + 말투 프로필 + 선호 예문 → 출력: 표현 3개(간결/부드럽게/명확하게) · 항목별 근거 구절 · 수정 이유 2~3줄. 출력은 JSON으로 고정. |
| 의도 체크 | 근거 구절이 실제 문장에 있는지 코드로 확인 (05장 ②) |
| 저장 | 로그인 없이 브라우저 저장(localStorage) — 말투 프로필 · 선호 예문 |
| 보안 | 홈·입력창에 “클라이언트명·금액 등 기밀 정보는 ‘A사’, ‘X원’처럼 바꿔 입력하세요” 고정 안내. 서버에 메시지 저장 안 함. |
| 미결정 | AI 호출 환경 · API 키 보호 방식 · 배포 위치 [빌드팀 기입] |

**콘텐츠팀(STEP 2)에 필요한 것**
- 카드 6개의 입력 질문 문구와 placeholder 예시
- 온보딩용 “어느 쪽이 나답나요?” 문장 쌍 2~3개
- 시연·테스트용 샘플 시나리오 (질문 · 일정 조정 부탁 · 상황보고 · 거절)
- UI 레퍼런스와 일반 GPT 비교 캡처 (P.11 벤치마킹)

## 11 검증 계획

**① 사전 미니 설문 · Before 근거 (조원 9명)**
1. 지난주 선배·상사에게 보낸 질문·부탁 메시지 1건을 쓰는 데 걸린 시간 (1분 미만 / 1~3분 / 3~5분 / 5분 이상)
2. 보내기 전에 다시 고친 횟수 (0 / 1 / 2 / 3회 이상), GPT 사용 여부
3. 최근 2주 안에 “그래서 뭘 해봤어?” 같은 되물음을 받은 경험과 상황 한 줄

**② 비교 사용자 테스트**

| 항목 | 설계 |
|---|---|
| 대상 | 우리 조 동기 / 신규입사자 (목표 5명 이상) [인원 · 날짜 팀 기입] |
| 상황 | 질문 · 부탁 · 상황보고 · 거절 |
| 비교 조건 | ① 평소 방식(일반 GPT 허용) ② 말결 — 순서는 사람마다 바꿈 |
| 정량 | 메시지 완성 시간 · 수정 횟수 · 원래 의도 보존 여부(누락 개수) |
| 받는 사람 평가 | 평가자 2명이 조건을 모른 채 평가: 추가 확인 질문 필요 여부 · 이해 쉬움(5점) |
| 정성 | 표현 만족도 · 실제 업무 사용 의향 · “다음엔 스스로 더 잘 작성할 수 있을 것 같다” · 자유 의견 |
| 결과 사용처 | P.09 숫자 칸, P.16~17 검증 결과, 프롬프트 수정 근거(P.13), decision-log |

결과는 실제 측정값만 기록한다. 측정 전에는 [측정 예정]으로 둔다.
