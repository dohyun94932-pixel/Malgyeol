| 피드백 연습장·거절도 괜찮아 추가 (입력 칸·샘플 응답·문장 틀은 content.js [임시]) | 기획안 5장 · 콘텐츠팀 문구로 교체 예정 |
| 거절도 괜찮아에 필수 칸 '받은 부탁' 추가 (기획안 칸: 의도 · 이유 · 대안) | 무엇을 거절하는지가 메시지에 없으면 뜻이 통하지 않음 · 빌드팀 제안, 기획팀 확인 필요 |
| 필수 칸(임시): 피드백 = 관찰한 사실 · 바라는 행동 / 거절 = 받은 부탁 · 의도. 나머지는 선택 | 기획안에 필수 여부 없음 · 내부 리뷰에서 점검 |
| 빈칸은 필수가 아니어도 되묻는 질문을 보여 줌 (버튼은 필수 칸만 막음) | 기획안 5장 "비어 있는 칸은 되묻는다", 6장 시연에서 '내 판단'을 되물음 · 확정 |
| 받는 사람: 상사 / 선배 / 동료 / 클라이언트 ('인차지' · '동기' 없앰). 호칭 문구는 [임시] | 기획안 5장 · 확정 |
| 표현 3종: 간결하게 / 부드럽게 / 명확하게. '내 말투안' 없앰. 말투 프로필은 3종 모두에 반영 | 기획안 5장 ② · 확정 |
| '명확하게' = 핵심 요청(과 기한)을 첫 문장에 두는 구조 | 빌드팀 정의(가짜 AI 기준) · 실제 AI 프롬프트에도 같은 기준 적용 예정 |
| 내 말투는 [저장]을 눌러야 반영 (이전: 누르면 바로 저장) | 기획안 6장 화면 ④ · 확정 |
| 피하고 싶은 표현은 앱이 붙이는 문장(인사·첫 문장·끝인사)에서만 뺌. 사용자가 직접 쓴 칸 값은 그대로 둠 | 사용자 의도(칸 값)를 바꾸지 않기 위해 · 빌드팀 결정 |
| 다시 만들기는 지금 가짜 AI라 같은 설정이면 같은 문장이 나옴 | 실제 AI 연결 전까지 유지 |

## 2026-10-04 · 빌드: 화면 디자인을 기획안 6장 시안 기준으로 1차 반영

| 결정 | 이유 · 상태 |
|---|---|
| 색·크기는 시안 이미지에서 직접 읽은 값 사용 (주황 `#FD5108` 등), `style.css` `:root` 변수에 모음 | design.md 도착 전 임시 · design.md 받으면 변수 값만 교체 |
| 홈 카드는 연주황 면, 화면 2 칸은 흰 면 + 연한 테두리 (작업 요청의 "연회색"과 다름) | 시안 기준으로 하기로 결정 |
| 상단 바(말결 로고 · 내 말투 버튼) 없앰. 화면 3에 [내 말투 설정] [처음으로] 글자 버튼 추가 | 시안에 상단 바 없음. 시연 4단계(결과 → 내 말투 → 다시 만들기) 경로 유지 |
| 화면 3은 라벨·제목 없이 세그먼트 탭부터 시작 | 시안 기준 |
| 결과 화면 버튼 이름 '이 표현을 내 말투에 반영' → '내 말투에 반영' (화면 읽기 프로그램용 이름은 전체 문구 유지) | 시안 · 버튼 두 개를 나란히 두기 위해 |
| 입력칸 글자 크기는 모두 16px (시안 값 15px보다 약간 큼) | iPhone Safari가 16px 미만 입력칸을 누르면 화면을 확대함 |
