[1단계 · 상태 점검 — 아직 아무것도 올리지 마]
- 이 폴더가 git 저장소인지, 원격(remote)이 위 주소로 연결돼 있는지 확인해 줘.
  연결이 안 돼 있거나 git 저장소가 아니면, 내 작업 파일을 잃지 않는 방법을 먼저 설명하고 승인을 받아.
- 원격 main의 최신 내용을 가져와(git fetch) 다른 팀원이 그사이 올린 변경이 있는지 확인해 줘.
- 바뀐 파일 목록(git status)을 보여 주고, 파일마다 무슨 변경인지 한 줄씩 설명해 줘.

[2단계 · 올리면 안 되는 파일 걸러내기]
- .env, .env.local, API 키, 비밀번호가 들어간 파일은 절대 올리지 마. .gitignore에 빠져 있으면 추가해.
- 작업용 임시 파일, 캡처 이미지, node_modules 같은 건 제외해.
- 올릴 것: 코드 변경, docs/말결_기획안_v1.1.md, docs/design/wireframe.png, docs/decision-log.md, docs/prompts/ 기록.
  (기획안 PDF 원본은 올리지 마. 텍스트판 .md만 올린다.)
- 최종적으로 올릴 파일 목록을 보여 주고 내 승인을 받아.

[3단계 · 브랜치에 커밋]
- main에 직접 올리지 마. 새 브랜치(예: feature/v1.1-align-design)를 만들어서 거기에 커밋해.
- 커밋은 작업 단위로 나눠 줘. 예:
  1) docs: 기획안 v1.1 텍스트판·와이어프레임 추가
  2) feat: v1.1 기준 카드 6개·받는 사람 4종·표현 3종 반영 (가짜 AI 유지)
  3) style: 와이어프레임 기준 화면 디자인 적용
  4) docs: decision-log·README 갱신
  커밋 메시지는 한국어로, 무엇을 왜 바꿨는지 알 수 있게 써 줘.
- 지금까지 이 작업에서 내가 너에게 준 주요 프롬프트와 결정 사항이 docs/decision-log.md와 docs/prompts/에
  날짜와 함께 정리돼 있는지 확인하고, 빠졌으면 채워 넣은 뒤 커밋해 줘. (평가 항목 3 'AI 활용 과정' 근거)

[4단계 · 업로드와 PR]
- 브랜치를 GitHub에 push해 줘. 로그인이 필요하면 내가 무엇을 눌러야 하는지 알려 줘(비밀번호를 나에게 묻지 마).
- push가 권한 문제로 실패하면 억지로 해결하려 하지 말고, 원인과 저장소 주인에게 요청할 내용을 알려 줘.
- 가능하면 main으로 합치는 Pull Request를 만들어 줘. PR 설명에는 바뀐 점 요약, 확인 방법(시연 시나리오 4단계),
  남은 일(콘텐츠팀 문구 교체, 실제 AI 연결 보류)을 적어 줘. gh가 없으면 웹에서 PR 만드는 방법을 알려 줘.
