## 프롬프트 원문

```
CLAUDE.md 규칙대로, 가짜 AI(ai.js)가 만드는 메시지를 고치자. 대상은 코딩 레퍼런스 5장 B1·B2·B3와,
지난 작업에서 찾은 어색한 문장("…검토해 주세요.을 부탁드립니다", "생각함 → 생각했습니다")이야.
고치기 전에 자동 점검 도구부터 만들어서 before/after를 숫자로 비교할 거야.

[1단계 · 점검 도구: scripts/check-messages.mjs]
- ai.js를 파일 수정 없이 Node vm 모듈로 불러와 실행. 데이터는 data/cards.json, data/malgyeol_sample_data.json.
  (Node가 없으면 먼저 알려 주고 브라우저에서 여는 qa.html 방식으로)
- 시험 대상: 샘플 30건 × 탭 3종 × 끝맺음 2종 × 요청 방식 3종. 그리고 일부 칸만 채운 사례:
  · T5: 상황보고에서 '완료한 것'만 채움
  · T8: s05 (막힌 점 "특별히 막힌 점은 없습니다.")
  · 예전에 문제가 났던 사례: 부탁 한 장 · 인차지 · 요청 "세무조사 대응업무를 저 대신 다른 사람이 나가주셨으면 좋겠어요" ·
    기한 "오늘 내로" · 필요한 결과 "가능한지 불가능한지" · 이유 "X사 업무의 과중" · 대안 비움
- 점검 항목:
  1) B1: 비어 있는 칸의 요청·기한·판단 문장이 붙었는지 ("확인 부탁드립니다", "시간 되실 때" 등)
  2) B2: 질문 준비실 마지막 문장에 '묻고 싶은 것'이 있는지, 해본 것·내 판단이 빠지지 않았는지
  3) B3: 수정 이유가 비어 있는 칸을 언급하는지
  4) 받는 사람: 선배님 / 인차지님(결론 먼저) / 동기(반말·짧게) / 담당자님(가장 격식, 합니다체)
  5) 문법 깨짐: ".을", ".를", "요를", "다를", "까지까지", "내로까지", "입니다입니다", 남은 "을를·이가",
     "null", "undefined", 공백 두 칸, 마침표 두 개
  6) 말투 혼합: 합니다체 설정인데 "~요."로 끝나는 문장, 해요체인데 "~니다." (동기·클라이언트 예외 규칙 반영)
  7) 마스킹('A사', 'X원') 유지, 의도 체크 근거 구절이 본문에 있는지, 피하고 싶은 표현이 들어갔는지
- 결과를 docs/qa/check-YYYYMMDD-before.md로 저장하고 항목별 개수를 표로 보여 줘.

[2단계 · 고치기]
- 핵심 원인: 샘플 칸 값은 완성된 문장인데, 문장 틀은 짧은 명사구를 끼워 넣는다고 가정하고 있어.
  그래서 칸 값을 먼저 판별해 줘: 완성 문장 / 질문 문장(?로 끝남) / 명사구 / 메모체(~함·~음) / "~지"형.
  · 완성 문장: 다른 문장 틀 속에 끼워 넣지 말고 한 문장으로 그대로 쓰기. 앞에 짧은 연결어만 붙이고(예: "먼저", "다만"),
    끝맺음만 설정에 맞추기(했습니다↔했어요, 생각합니다↔생각해요, 주세요 → 주시겠어요?/주실 수 있을까요? 등).
  · 질문 문장: 그대로 쓰기. 받는 사람 규칙에 맞게 끝만 다듬기.
  · 명사구·메모체·"~지"형: 어울리는 문장 틀을 따로 써서 자연스럽게 잇기. 기한 끝의 "까지·내로·중" 뒤에 "까지"를 또 붙이지 않기.
- B1: 비어 있는 칸은 문장에서도 빠지게. 앱이 고정으로 붙이는 요청 문장은 해당 칸(도움 요청 등)이 있을 때만.
  급한 기한(오늘·지금·바로 등)에는 여유 있는 끝인사("시간 되실 때")를 쓰지 않기.
- B2: 질문 준비실은 '묻고 싶은 것'을 마지막 문장에 그대로. 필수 칸이 비면 [메시지 만들기]는 계속 비활성.
- B3: 수정 이유를 '조건부 문구 목록'(채워진 칸 · 선택한 탭 · 받는 사람에 따라 고름)으로 바꾸고 2~3줄로 제한.
  탭마다 이유가 달라야 해(내 말투안 / 더 간결하게 / 더 부드럽게).
  수정 이유 문구를 cards.json에 넣을지 content.js에 둘지 장단점을 먼저 설명하고 내 선택을 받아.
- 받는 사람 말투 규칙: 동기는 반말, 클라이언트는 합니다체 고정으로 내 말투 설정보다 우선. 선배·인차지는 내 말투 설정을 따름.
  (팀 확정 전 임시안이니 decision-log에 '확인 필요'로 적어 줘)
- 사용자가 쓴 핵심 내용(날짜·시간·숫자·마스킹·요청 대상)은 절대 바꾸지 마. 끝맺음만 바꾸는 건 괜찮아.
- 의도 체크 근거 구절은 끝맺음을 바꾼 뒤에도 본문에 글자 그대로 들어 있게(끝맺음 앞부분까지만 근거로 쓰는 식).

[3단계 · 확인]
- 점검 도구를 다시 돌려 docs/qa/check-YYYYMMDD-after.md로 저장하고 before/after 비교표를 보여 줘.
- 시연 흐름(코딩 레퍼런스 2장 7절) 4단계를 다시 따라가고, 샘플 q01·r02·s01·q03(동기)·r05(클라이언트) 결과 문장을 그대로 보여 줘.
- 가짜 AI로는 해결이 어려운 것은 따로 정리해 줘(실제 AI 연결 때 참고).
- decision-log 기록, 코딩 레퍼런스 5장 B1~B3 반영일 기입, docs/prompts/에 이번 프롬프트와 개선 과정 기록, 커밋(push X).
```

## AI가 틀렸다가 고친 것 (개선 과정)

| 발견 | 원인 | 처리 |
|---|---|---|
| 점검 도구가 "자료가 없습니다", "확신이 없습니다"를 '없음' 칸으로 셈 (B3 147건 중 63건이 오탐) | '없음' 판정 규칙이 너무 넓음 | "특별히·별다른·딱히 … 없습니다" / "없음"만 '없음'으로 보도록 좁힘 |
| 점검 도구가 "기한은 수요일 오전까지입니다"를 "가능한지입니다"류 오류로 셈 (56건) | "까**지**+입니다"를 "~지+입니다"로 봄 | "까지" 제외. 고치기 전 코드를 잠시 되돌려 같은 기준으로 before를 다시 측정 (910 → 854) |
| 인차지 '결론 먼저'와 B2 '질문은 마지막'이 질문 준비실에서 충돌 | 두 규칙이 같은 칸(묻고 싶은 것)을 요구 | 질문 준비실 인차지의 결론 = '내 판단'으로 정함(점검 기준·코드 모두) |
| 점검 페이지가 실행되지 않음 | 점검 파일과 content.js·ai.js가 같은 이름(URGENT_RE, LEAD_FIELD, MEANS_NONE_RE, splitSentences)을 씀 — splitSentences는 ai.js 함수를 덮어쓸 수 있었음 | 점검 쪽 이름에 QA·qa를 붙여 분리 |
| 숫자는 0인데 읽어 보니 어색: "다만 특별히 막힌 점은 없습니다" · 동기 "내 생각엔 … 맞다고 생각해" · 이유가 맨 끝("…알려 주시면 감사하겠습니다. X사 업무의 과중 때문입니다.") | 점검 패턴에 없는 어색함 | '없음' 값엔 연결어 생략 · 반말 판단 연결어 제거 · 부탁 한 장은 이유를 요청 바로 뒤로 |

## 가짜 AI로는 해결이 어려운 것 (실제 AI 연결 때 참고)

| # | 내용 | 예 |
|---|---|---|
| 1 | 불규칙 활용·드문 끝맺음은 바꾸지 못하고 그대로 둠 | "모릅니다"(르 불규칙), "~죠", "~네요", "~거든요" |
| 2 | 명사구 칸을 문장으로 만들 때 딱딱함 | "기한은 오늘 중 회신입니다", "(상대 확인: 필요 (연장 승인))", "선택지는 ① … 진행입니다" |
| 3 | 사용자 문장 속 높임·내부 용어는 그대로 | 동기에게 "보내주실" 같은 높임이 남을 수 있음 · 클라이언트에게 내부 용어("인차지", "조서") 걸러내기 불가 |
| 4 | 탭 3종의 차이가 첫 문장·끝인사·나열 방식 위주 | '내 말투안'과 '더 부드럽게'의 본문이 같음 (실제 AI는 본문 어조까지 바꿀 수 있음) |
| 5 | 질문 준비실의 요청 방식 차이는 첫 문장에서만 보임 | B2(질문이 마지막)를 지키려고 끝인사를 붙이지 않음 |
| 6 | 문장 길이 '짧게'는 끝인사만 빼는 수준 | 내용 요약·압축은 못 함 |
| 7 | 동기에게도 '내 말투안' 수정 이유가 "내 말투 설정에 맞춰…"로 나옴 | 동기는 반말 규칙이 설정보다 우선이라 문구가 정확하지 않음 → 문구 조정 필요 (콘텐츠팀) |
| 8 | 점검 도구는 정해 둔 패턴만 찾음 | 0건이어도 어색한 문장이 있을 수 있어 사람이 읽어 봐야 함 |
